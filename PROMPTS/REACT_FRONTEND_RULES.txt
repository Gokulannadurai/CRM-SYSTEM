================================================================================
                                NAMING CONVENTIONS
================================================================================

1.  COMPONENT NAMING:
    - Use PascalCase for component names (e.g., UserProfile, CustomerList)
    - Use descriptive names that clearly indicate the component's purpose
    - Suffix components with their type: Page, Component, Container, Hook, Context
    - Use index.js for default exports in component folders
    - Avoid abbreviations unless they are widely understood (e.g., API, URL, HTTP)

2.  FILE & FOLDER NAMING:
    - Use kebab-case for file and folder names (e.g., user-profile.tsx, customer-list.tsx)
    - Use PascalCase for component files (e.g., UserProfile.tsx, CustomerList.tsx)
    - Use camelCase for utility files (e.g., apiUtils.ts, validationUtils.ts)
    - Use UPPER_SNAKE_CASE for constants files (e.g., API_ENDPOINTS.ts, ROUTES.ts)
    - Organize files by feature, not by type

3.  VARIABLE & FUNCTION NAMING:
    - Use camelCase for variables and functions (e.g., userData, handleSubmit)
    - Use descriptive names that clearly indicate the purpose
    - Use boolean prefixes for boolean variables (e.g., isLoading, hasError, isVisible)
    - Use verb-noun combinations for event handlers (e.g., handleClick, onSubmit)
    - Use meaningful names for state variables (e.g., userList, selectedItem)

4.  CONSTANT NAMING:
    - Use UPPER_SNAKE_CASE for constants (e.g., API_BASE_URL, DEFAULT_PAGE_SIZE)
    - Use camelCase for exported constants (e.g., apiEndpoints, validationRules)
    - Group related constants in separate files
    - Use descriptive names that clearly indicate the constant's purpose

5.  HOOK NAMING:
    - Use camelCase for custom hooks (e.g., useUserData, useApiCall)
    - Prefix with 'use' for all custom hooks
    - Use descriptive names that indicate the hook's functionality
    - Avoid generic names like 'useData', 'useState'

================================================================================
                                COMPONENT STRUCTURE & ORGANIZATION
================================================================================

6.  COMPONENT STRUCTURE ORDER:
    - Import statements (React, third-party, internal)
    - Type definitions and interfaces
    - Constants and static variables
    - Component function declaration
    - Hooks (useState, useEffect, custom hooks)
    - Event handlers and utility functions
    - Render logic and JSX
    - Export statement

7.  COMPONENT SIZE & COMPLEXITY:
    - Keep components under 200 lines of code
    - Maximum 5-7 props per component
    - Extract complex logic into custom hooks
    - Use composition over inheritance
    - Break large components into smaller, focused components

8.  COMPONENT RESPONSIBILITY:
    - Single Responsibility Principle: Each component should have one purpose
    - Separate presentation from logic using custom hooks
    - Use container components for data fetching and state management
    - Use presentational components for UI rendering
    - Avoid mixing business logic with UI logic

9.  FOLDER ORGANIZATION:
    - Organize by feature, not by type
    - Use index files for clean imports
    - Group related components together
    - Separate shared components from feature-specific components
    - Use consistent folder structure across the project
